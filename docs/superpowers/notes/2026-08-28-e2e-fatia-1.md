# E2E do critério da Fatia 1 — COMPLETO, com UI (T10 do Plano C)

Roteiro executado com o usuário/piloto no domínio público **https://aios-pocket.vercel.app** entre 2026-08-24 e 2026-08-28. Stack de produção inteira: web na Vercel (projeto `aios-pocket`, root `apps/web`) → API no EasyPanel (imagem GHCR da branch `plano-c-inbox-realtime`, deployada via `workflow_dispatch` em 2026-08-24) → Supabase (banco vivo + Realtime) → Evolution dev → WhatsApp real.

## As 5 partes do roteiro

**1. Mensagem real → aparece no inbox público.** Mensagem de WhatsApp real (2026-08-24 11:28 BRT) entrou pelo webhook → pipeline → Supabase e apareceu na conversa do domínio público. Entre 24 e 28/08 o sistema rodou com **tráfego real de uso** (549 mensagens no total, ~72 novas no período) — soak test de produção involuntário e bem-sucedido.

**2. Resposta pela UI → chega no celular.** Resposta enviada pelo composer real da página pública (2026-08-24 11:30): bolha "você — Aios Pocket", 202 → worker → Evolution → celular; acks progrediram até ✓✓ (`delivered`/`read` conferidos no banco — `read` só existe se o destinatário recebeu e leu).

**3. Resposta do celular do piloto → "você — celular".** Provada com tráfego real: mensagens enviadas do celular em 2026-08-28 12:05–12:08 BRT entraram como outbound `fromMe` e exibem "você — celular ✓✓" no inbox público (ex.: "Olá Viviane…" 12:08).

**4. Timeline conferida no banco.** 1136 `customer_events`; os mais recentes `message_sent_from_phone` correspondem 1:1 às mensagens da parte 3, com `correlationId` e `schema_version: 1`.

**5. Badge/banner de conexão.** Teste real do cenário de logout (o mesmo 401 de 2026-08-11): piloto desconectou a sessão pelo celular → webhook `CONNECTION_UPDATE close` → `connectionState=disconnected` no banco → **banner vermelho "instância desconectada" apareceu na tela** (atestado pelo usuário). QR novo gerado via API, escaneado → `open` às 21:57:04 BRT → `connected` no banco → banner some no poll seguinte (~30s).

## Latência realtime (medição honesta)

Single-clock (PC), POST na API do EasyPanel → bolha no DOM da página pública: **2,79s** (2026-08-28). Desconta-se ~0,5–1s de POST+insert (rede residencial→EasyPanel→Supabase us-west-2): o trecho insert→tela fica em ~1,5–2,2s — borderline no critério "<2s" do plano. Funcional e imperceptível no uso; otimização registrada no carry-over (reduzir debounce de 300ms; fast-path mapeando o INSERT direto para a conversa aberta, sem refetch).

## Achados novos (para o carry-over)

- **Watchdog de morte silenciosa**: o badge reflete `Company.connectionState`, alimentado por webhooks. Evolution MORTA (processo parado) não emite webhook — o estado congela em `connected` e o banner nunca acende. A v1 cobre desconexões *reportadas* (logout/close); healthcheck ativo da instância é trabalho futuro.
- **Restart da Evolution não derruba a sessão**: `POST /instance/restart` reconectou tão rápido que nenhum `connection.update` foi emitido — inútil para testar o banner; o teste real é logout.
- **Manager UI da Evolution**: deep link `/manager/instance/undefined/dashboard` (favorito antigo) trava em spinner infinito; entrar pela raiz `/manager` resolve. Não é incidente de infra.
- **Latência da suíte**: testes de integração desta máquina contra o droplet flakeiam com timeout default de 5s do vitest (fix aplicado no teste da corrida do eco em 2026-08-23).
